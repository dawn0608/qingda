# 回调处理

回调先持久化再确认。`events`和`callback_versions`保存可核验的原始输入及变化，正文共用`message_contents`；平台ID按字符串处理。账号、会话、终端与用户归属都须核验，重复回调不得重复生成任务。

`protocol`解析文本、图片、语音、视频、引用、文件和系统事件。卡片只有明确可提取的文本才参与相应上下文，不推测金额、支付进度或未知字段。`message_views`保存可用性和撤回状态，`message_effects`保存待关联效果，`message_aliases`关联平台ID。管理台不提供聊天浏览、媒体下载、消息搜索或历史修复接口。

撤回按原平台ID及会话范围关联，支持乱序；使未发送输入和生成结果失效，已进入发送边界的任务保留真实结果。文件完成通过明确的overwrite关联更新，不凭文件名和时间猜测。真实引用须核对原消息，撤回内容不进入后续上下文。

`ModContacts`更新实际提供的资料并触发关系核实；`DelContacts`保存删除与退群证据；其他成员退群不代表本账号退群。`Offline`维护离线状态及未发送任务取消。未知或独立朋友圈、视频号事件保留输入，不扩大业务能力。

好友验证消息仅在核实身份后将有效问候关联到好友会话，不自动通过申请或主动问候。AI准入见[媒体规则](media.md)与[群聊唤醒](group-wakeup.md)。真实失败案例继续保留在回调、撤回与好友消息回归中；历史发布过程由Git及受保护发布证据保存。
