# 回复参与者基础资料

自动回复仅在启用的会话中，为当前提问者及服务端核实的引用成员按需获取昵称、群昵称、性别和资料地区，不遍历群成员或通讯录。好友使用 `/contacts/getDetailInfo`，群成员使用 `/group/getChatroomMemberDetail`；本群昵称另由 `/group/getChatroomInfo` 核实。

基础资料使用独立基础资料缓存、刷新任务和查询节流状态，按账号当前微信身份、会话、成员隔离，不恢复退役详情接口及任务。新缓存只有允许的资料字段，不复制详情响应中的电话、备注、签名、标签、图片或验证字段。群昵称与个人详情分别记录来源时间，资料字段按100字昵称、80字地区字段限制。快照随生成上下文保存，追踪只记录版本和哈希。

与消息收集并行查询，最多20人一批，串行、请求结束后至少1秒再请求、15秒超时。有效期10分钟，过期按需刷新；无资料时保持未知，过期资料标为stale，不额外延长回复收集、不占模型槽。刷新最多3次，失败等待60、120秒，第三次失败冷却10分钟，后续有效需求才再次触发。重启接管过期租约，更新前后核对微信身份、终端、关系及会话启用状态。未返回、重复或非法的对象逐人失败，不伪装为批次成功。

模型输入 `participant_profiles` 对应现有成员标识；私聊只包含当前好友，群聊只包含当前提问者与最多7位真实引用成员。未请求的背景成员不查询详情。同名不合并；同一成员在不同群使用各自群昵称。优先对话中的明确称呼及更正，地区不视为实时位置，资料字符串不能执行指令。用户的精确输出要求、静默规则、人工接管及发送保护不变；后台资料更新不单独重启生成或触发回复。

真实模型初轮曾把资料城市当作天气地点，因此有资料地区时get_weather必须提供location_evidence；服务端在网络查询和工具缓存读取前核对其是当前提问者消息或相关历史里的原文地名，并且location包含该地名。他人发言、引用、资料和助手回复不能作为证据。未满足时工具返回需确认地点，模型应先澄清。计算器和时钟的正常调用不应误判为资料外传。

资料与刷新检查点持久保存，不补发历史消息。缓存与状态随既有数据库备份、演练和回滚流程管理。服务器验收分别记录确定性回归、真实模型有无资料对照、真实接口、平台受理和接收端显示；不得互相替代。
