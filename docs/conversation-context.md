# 私聊与群聊上下文及历史回查

## 容量与归属

使用服务端固定的 DeepSeek 官方 `deepseek-flash`，用户不能更换型号，调用使用当前用户的模型密钥。当前模型的公开容量为1M，本应用每次完整请求输入限定 128000 tokens，生成默认输出额度16384 tokens、文本累计预算120秒由服务端统一管理；原有有限截断恢复和240秒任务总截止时间继续生效。文本另限 2 MiB，请求体继续限 48 MiB。官方 tokenizer JSON 随包发布，加载时校验 SHA256，不执行供应商 Python 或远程代码。

私聊最多 12 个完整轮次、48 条、12000 tokens；群聊当前提问者最多 8 个完整轮次、32 条、8000 tokens。群聊背景最多 6 条、1000 tokens，计入群聊历史预算。先按成员和真实问答关联查询，再限制数量，避免全群最近消息淹没该成员的历史。没有跨日过期；时间信息保留。

轮次通过 tasks.handled_message_ids 与真实发送记录关联。人工手机发言始终为 owner；静默、失败、排队不伪造助手发言。已回答问题被撤回或不可见时，不保留无来源的答案。消息、自动回复和平台同步副本去重。

当前问题、更正、真实引用、已释放的等待材料和最近仍有效的澄清优先；先移除背景和较远完整轮次，再让可选资料让出容量，不截断当前问题或引用后声称完成。历史相关静态图片沿用现有上下文及容量边界，以真实像素提供给deepseek-flash，不使用旧视觉摘要。图片来源、贴图表情排除及唤醒策略保持不变。

## 只读历史工具

search_conversation_history 仅在已获准回复的任务内使用。账号、微信身份、会话与回复对象由服务端绑定，不接受模型传入其他账号或会话。支持消息原文、已有语音转写、关联真实答复、北京时间日期范围和已有消息锚点；先匹配原词组，无结果再尝试空格分隔关键词共同匹配；所有查询先限定账号、会话、成员及时间范围。

私聊范围是当前好友会话。群聊默认只有当前成员与助手的交流；扩大到其他成员讨论须提交当前消息 ID、逐字依据和该依据出现的主题词，或已核实引用的锚点；同名成员要求引用确认。搜索返回原文、作者、时间和轮次，不改变 reply_target，不进入 handled_message_ids，不创建回复任务。

每次生成最多两次回查，每次最多 8 轮、40 条、12000 tokens，查询总耗时上限两秒。次数与结果引用持久化，同一调用重启恢复不重新消耗次数，失去任务所有权不得落库。无结果与超时分别表达；不能把查询失败当作“没有这段历史”。

历史只帮助完成当前问题，不补答旧请求。旧单次精确格式和停止指令不控制新一轮；明确持续约定可以参考，当前更正优先。旧地点、天气、价格、搜索结果不能冒充当前事实，助手旧答案不是独立事实依据。没有人物画像、长期摘要、跨会话记忆或主动跟进。

天气地点取证限定本轮实际发言及相关拍前候选；历史行程、旧地点和资料地区不能直接授权当前天气查询。图片像素与创作来源分别处理，没有来源证据时只评价可见特征。历史中尚未完成的旧问题也不能引发额外工具查询。

普通回答不设200字硬上限，也不触发额外压缩调用。日常问题简短，复杂、多问题、写作与代码按需展开；精确输出保留原字符。协议纠错及截断恢复仍有界，文本累计预算不变。

模型输入显式包含 history_coverage 的范围、最早/最新时间、是否存在未加载原文及删减原因。近期未加载不等于从未说过。群聊候选媒体须有明确素材承接措辞；普通问候不携带无关历史图片。

## 检查点与迁移

检索索引及reply_context_snapshots支持按任务恢复。每个输入修订固定消息清单、顺序、角色、内容哈希、资料快照和策略版本；历史正文不复制进新清单。工具检查点同样保存原文引用，恢复时重新读取并校验。正常旁观者新消息不改变已冻结输入；撤回、更正、权限变化和人工接管仍使旧结果失效。

快照写入核对任务租约，查询等待不持有跨模型或网络事务。进行中任务所需清单纳入现有备份、维护和恢复契约。恢复服务使用同结构修复版本，始终保留最新业务数据。

## 回复上下文查看

聊天记录中点击助手回复气泡，或聚焦气泡后按 Enter／空格，打开“AI 回复上下文”。“上下文”展示生成当时的实际系统提示词（包含助手设定和号主资料）、参与者资料、相关历史、群聊背景、当前消息、引用、等待期间材料和实际附带图片。长提示词可展开全文；顶部说明加载范围、历史数量、时间、未加载原文与删减原因。输入 tokens 为请求容量估算，供应商实际用量在对应调用详情中查看。

“生成过程”按执行顺序展示等待补充判断、模型请求、工具参数与结果、决策修复及截断恢复，包含最后的 finish_reply／finish_input_control 校验结果。每次请求可展开并复制脱敏原始 JSON；只读查看不触发模型、工具、媒体下载、任务重放或微信发送。

`context_capture` 在 Gateway 实际请求组装及容量检查后捕获业务输入，保持消息数组、字符串正文和本轮时钟，不根据当前配置重建。图片字节替换成来源消息、位置、像素 SHA-256 和尺寸，读取已有缓存时再次核验，不另存 Base64。应用凭据和思考正文不进入记录或接口，声明排除项不等于记录缺失。

记录复用 `reply_execution_events`，不新增表或迁移。正文和工具定义按任务内规范 JSON 哈希复用，调用仍按输入修订、生成批次和调用编号绑定。最终任务 `trace_json.context_capture` 保存预期调用清单；检查点在既有 `usage_json` 的内部 `_context_capture` 字段原子保存链路，加载后剥离，不混入模型用量或下轮请求。输入指纹或修订变化不沿用旧链路；旧块只能被新链路明确引用后展示。

每个 Gateway 的后台缓冲最多 32 MiB／256 条，记录不增加回复链路的数据库等待。缓冲满、写入失败、进程退出丢失或缺少请求／响应／工具配对时，继续正常回复并标记不完整；后续重新读取可看到已完成的后台写入。仅向所属用户及任务写入，失去租约不能创建有效新链路；已清空任务不接受迟到记录。上下文记录按业务历史持续保留，并随原有会话清空及备份契约处理。

旧回复仅展示现有清单中通过来源哈希校验的正文和已有工具记录，标注“旧回复未记录完整上下文”。系统提示词、完整请求或原文无法核验时不补造，完全没有证据时显示不可用。

接口与交互见[聊天记录](frontend-design.md)，清空范围见[清空聊天记录](chat-history-deletion.md)。

## 验收

完整后端回归及独立进程恢复沿用专用 Linux/PostgreSQL 隔离环境；真实模型对照与性能检查须在已授权范围执行。本地或 CI 可执行静态检查、前端测试及构建。用长历史分别在开头、中间、末尾植入已标注事实，检查新旧窗口差异、对象隔离、后续更正、历史注入、过期地点、精确输出与图片回归。关键模型案例固定三次，不挑选通过回执。

真实微信由 Dawn 私聊及微信自动化测试群补验。程序、模型输入、平台回执、用户实收分开记录；发布版本和验收回执写入本次发布目录。未取得实收证据不能标为完整通过。
