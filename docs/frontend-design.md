# 管理台视觉与交互

## 工程契约

沿用 React、TypeScript strict、Vite、npm 与现有组件体系。对接有 OpenAPI 契约的服务时生成类型和客户端，不手改生成物；外部数据及流式事件做运行时校验。浏览器构建只接收公开配置，API 优先相对路径并经统一对外入口转发；构建时注入的变量变化后须重建。认证后的业务配置读取遵循各自的用户范围与脱敏规则。

复用现有 Node 测试，浏览器核验按布局和交互影响选择 Playwright 场景，覆盖必要的桌面、窄屏和短窗口；保持内容可达，不隐藏滚动条掩盖问题。具体入口见本文验收部分及[验收说明](verification.md)。

## 统一主题

全前端采用清新薄荷青绿主题，减少灰绿色叠加，以柔和底色、清透导航和小面积鲜活操作色建立层次。沿用青答品牌资源、当前布局、字号、控件尺寸、圆角和操作流程。

网页界面字体统一使用公共主题的 `--font-ui`：英文及数字优先Inter，中文Noto Sans SC，正文400、按钮及关键标签500、标题及强调600。登录、管理台、账户弹窗、顶部提示和Markdown正文共用；代码块及源码使用 `--font-mono` 等宽字体。字体由本站提供，不依赖外部字体服务，字库覆盖范围及哈希见字体资源文档。

微信管理和助手共用头像组件，优先高清头像，失败依次回退小图与原占位图；地址变化重新加载，保持现有尺寸和裁剪。用户头像沿用独立认证地址，新上传画质见[账户设置](account-settings.md)，不重新压缩历史头像。

颜色由 `frontend/src/theme.css` 集中维护，页面和组件使用语义变量，不各自固定颜色：

| 用途 | 颜色 |
| --- | --- |
| 薄荷青绿导航 | #DDF3E8 → #F1F9F4 |
| 品牌操作色／品牌文字 | #13836B／#116D59 |
| 装饰辅助色 | #39B88E |
| 页面底色 | #F2F7F4 |
| 内容表面 | #FDFEFD |
| 正文／辅助文字 | #293C36／#5B7068 |

- 浅青绿渐变用于桌面侧栏和窄屏底部导航，配合深青文字；当前入口使用稍浓的浅青绿色块与细边框。导航文字、辅助文字、边框、悬浮和键盘焦点使用独立变量，账户弹窗继续使用正文配色。
- 顶栏与卡片标题区使用 #E8F7EF → #F7FBF8 的轻薄渐变；表头、查询工具区和分页使用更浅的表面色，导航选中项使用 #CBEFDB → #E1F6E9。主按钮使用 #13836B → #147E70，正文区域保持微染白底。
- 品牌填充使用 `--brand`，文字与链接使用 `--brand-ink`，深色按钮前景使用独立的 `--on-brand`；不得将文字色直接用作选中控件填充，或将内容表面色兼作按钮前景。辅助色仅用于登录插画等小面积图形。悬浮、按下保持逐级加深，阴影降低绿色染色和厚重感。
- 面板、浮层和弹窗使用不同的阴影层级。侧栏账户菜单贴合入口、同宽、无外侧圆角及阴影，使用浅青背景；退出操作以深红文字、浅红底及对应焦点表达。
- 成功、警告／暂停、错误和普通信息分别采用绿、琥珀、红和蓝青色，同时保留明确文字或图标。通知根据现有 success／error／info 类适配，不改变提示时序。
- 所有按钮、输入框、选择器、分类切换、复选框、开关、头像、标签、分页、菜单和弹窗统一覆盖默认、悬浮、按下、聚焦、选中、禁用、只读和错误状态。普通文字对比度至少4.5:1；禁用控件仍应可辨识，只读字段保持可读。
- Markdown 标题、链接、引用、代码、表格、选区和草稿反馈沿用相同变量；第三方编辑器覆盖限定在编辑器容器内。编辑正文节点保持透明、无额外边框，不改变光标、选区、撤销或输入行为。
- 登录注册、账户设置授权／列表／详情／底部操作区及备案信息均使用该主题。静态渐变不增加持续动画、外部字体、图片或动画依赖。

## 页面与组件契约

当前保留「微信管理」「智能助手」「系统设置」三个导航入口。聊天浏览仅通过回复范围中的只读弹框提供，不恢复独立消息管理、聊天详情及任务记录页面。

桌面使用左侧导航和固定顶栏，窄屏使用底部导航。三个页面共用主内容区边距：桌面24px，780px及以下16px；顶部标题和内容左边界对齐。

### 微信管理

沿用九列居中表格、响应式分页及窄屏卡片，保留原列宽、行高和分页计算。表头、交替行、悬浮、在线／离线状态及分页按主题配色。只读展示账号资料，不增加微信登录、消息发送或数据修改入口。

### 智能助手

智能助手及系统设置的五个主面板共用 `PanelHeading`：浅绿渐变、3×16px短竖线、14px半粗标题，桌面44px／窄屏40px高，上下内边距分别6px／4px；标题居左，已有状态和操作居右。不保留标题下方说明。连接电脑和通知接收等内部标题保持13px的次级层次。标题字号小于页面顶栏。

两页不提供手动刷新入口，回复范围沿用1秒自动读取；微信接入每次读取结束5秒后更新，并在返回可见页面或窗口重新获得焦点时读取。自动读取在页面隐藏时暂停、返回时恢复，读取不重叠，离开时取消；失败保留最近有效内容并自动恢复，连续失败沿用顶部通知去重。Token正在编辑时保留输入及原始配置版本，提交期间暂停轮询。助手草稿及中文输入规则保持原约定。

顶部左侧为紧凑账号卡，右侧为「启用助手」；保留当前账号卡自适应宽度、44px高度、贴边真实头像和昵称省略规则。这一行到上方页面标题栏及下方面板的间距共用 `--page-spacing`，桌面均为24px、窄屏均为16px，不叠加行内底部留白。下方助手设定与回复范围使用同高标题区及10px圆角外框。宽度大于1100px时按3／2分配、回复范围至少360px，其余上下排列；正文与联系人在各自区域滚动，查询工具和分页固定可见。

左侧编辑列包含上方「助手设定」与下方「号主资料」，间距20px、两块等高，整体顶部和底部分别与回复范围对齐。两块共用原标题带、10px圆角和编辑器，标题固定；正文超出时显示细滚动条，源码模式同样仅在正文内部滚动。窄屏编辑列整体在上、回复范围在下，编辑列内仍等分。号主资料留空时提示「填写允许向好友和群聊公开的号主资料」，无账号只读留空。

无微信账号时，顶部展示44px高的「暂无微信账号」静态头像卡片，不显示下拉箭头；助手设定只读预览现有默认模板，接入账号后沿用该账号设定和草稿；回复范围空状态文案在标题下的正文区域水平、垂直居中。预览不创建账号或保存草稿。

回复范围分类、搜索及状态筛选同排，固定每页10条；列表按可用高度分配行槽，不足10条保留空位。窄屏、矮窗口、暂停说明与长名称仍保持可读，不裁切分页。回复暂停使用琥珀色标签，恢复操作与正常开关继续保留服务端禁用和确认语义。

搜索及分页沿用只读 PostgreSQL 查询，不读取聊天正文；中文组词期间不发搜索，300ms去抖、过期响应丢弃和失败保留上次有效结果继续有效。详见既有回复范围接口及 `evals/acceptance/reply_scope_layout_browser.py`。

每行右侧成组排列“聊天记录”和回复开关／恢复按钮：记录入口使用会话图标与文字，操作间以短竖线分隔；操作控件右边缘与上方状态筛选框右边缘对齐，桌面和窄屏保持一致。默认背景透明，记录入口使用1px主题细边框与6px圆角，悬停时显示浅绿反馈，不加阴影；按钮边框与开关到分隔线的留白对称，常规宽度两侧各12px，面板宽度不超过360px时各8px。两个控件独立响应，记录入口不受回复开关、暂停或关系移除状态禁用。弹框沿用原生 `dialog`、全站主题和顶部提示，标题显示联系人／群名；搜索栏固定、正文独立滚动，桌面最大900px宽、760px高，窄屏四周至少16px留白。Esc、关闭按钮或点击遮罩关闭，焦点回到原入口。

聊天记录默认读取最近50条并定位底部，上滚按稳定游标加载更早消息，保持当前阅读锚点。查看与搜索不受回复开关或模型上下文容量限制，不触发微信发送。每条展示发送人、上海时间、收发方向、完整正文和已有媒体文字；群聊包含所有成员的已保存聊天，助手回复与回调共用收发去重。后台通知和系统条目不展示；已撤回原文保留并标注，未知聊天类型显示“其他消息”及可提取文字。XML只作安全解析，不作为HTML渲染或暴露下载凭据。

普通静态图片仅展示已有、已确认静态的像素缓存，气泡缩略图最大240×200px并按原比例预留空间，点击或键盘操作打开大图；大图沿用原生dialog，Esc优先关闭大图并回到原图片。无缓存保留“[图片]”，缓存读取失败显示“[图片暂不可用]”，主动查看失败使用现有顶部提示。打开、滚动和搜索记录均不触发媒体补取、转写、模型调用或任务重放；贴图、动态图片与视频保持类型占位。语音沿用微信式横向气泡、声波和秒数，已有转写显示在下方；点击或键盘播放已有原音，再次点击暂停，播放时声波动画，同一时间只播放一条。关闭、切换会话、搜索或隐藏页面即停止；无缓存或播放失败使用顶部短提示，不补取或重转写。

收到与发出的正文复用后端 `native_emotions.json` 统一词表，将已知内置文字表情及别名呈现为20px行内图标；未知标记和图标失败时保留原文。原始别名、换行和文字继续用于搜索、高亮、复制及无障碍描述。图标为固定归档的微信官网原始静态资源，来源与SHA-256见前端素材清单，随本站构建发布，不运行时外链；构建检查词表完整覆盖与文件哈希。

弹框搜索在组词结束后300ms读取，覆盖该会话全部展示正文、标题、文件名、消息类型和已有语音转写，以匹配记录替换正文并高亮；清空搜索恢复原聊天和阅读位置。搜索扫描和结果均可续页，不能把空扫描批次视为无匹配。非搜索模式每5秒读取新增记录并更新最近记录，底部跟随、历史阅读不跳动；隐藏、关闭或切换账号时取消请求，失败保留当前内容并自动恢复。无消息显示“暂无已保存的聊天记录”，无匹配显示“没有匹配的聊天记录”。

专用只读接口为 `GET /wechat/api/v1/accounts/{aid}/conversations/{cid}/history`，支持 `q`、历史 `cursor`、新增 `after_id` 和默认50、最多100的 `limit`；历史游标与新增水位互斥。返回 `items`、`has_more`、`cursor`、字符串 `watermark`、清空修订 `history_revision` 及可空 `clearing` 状态，消息ID同样以字符串返回。游标绑定账号、会话和关键词，查询沿用服务端认证及RLS，不读其他用户记录，不写业务数据或重放任务。清空修订变化时淘汰该页面的原记录、搜索与滚动缓存，不合并删除前的迟到响应。

助手回复气泡可点击，支持 Enter／空格；选择复制正文、图片及语音操作不会误开上下文。新弹框标题为“AI 回复上下文”，沿用原生 dialog、主题和顶部提示，最大1000px宽／820px高，窄屏四周至少16px。标题及“上下文／生成过程”切换固定，正文独立滚动；系统提示词可展开全文，实际输入按来源分区，调用详情和脱敏原始 JSON 按需展开。Esc、遮罩和关闭按钮只关闭顶层，恢复到原气泡且不改变聊天位置。读取失败可重试，记录不完整与旧回复缺失原因直接显示；关闭、搜索、切换账号／会话、清空或历史修订变化后中止读取，迟到响应不回填。

新增 `GET .../history/{mid}/context` 返回 `status=complete|partial|unavailable`、`missing`、`input`、`calls`、`cursor` 和 `has_more`；`call_id` 按需读取某次请求／响应或工具详情，调用列表默认50、最多100，游标绑定消息及最终生成清单。`GET .../history/{mid}/context/images/{sha256}` 仅读取该回复快照确实引用的同会话匹配像素。两接口均认证并禁止缓存，未登录401，越界、非助手消息或不可见资源统一404。聊天列表沿用 `source=auto` 与字符串消息编号，不预加载上下文。记录语义及缺失边界见[上下文](conversation-context.md#回复上下文查看)。

搜索框右侧提供紧凑的“清空聊天记录”。点击打开同主题原生确认弹框，显示当前好友／群聊名称，默认焦点在取消；Esc或遮罩仅关闭确认层并恢复焦点。确认后立即防止重复提交并停止语音播放，清理中禁用搜索及清空按钮，完成后恢复完整会话视图及顶部成功提示。当前搜索词和分页不限制删除范围；确认之后收到的新消息保留。清理失败保持进度并自动续清，不把部分完成当成功。接口、关联数据与磁盘文件边界见 [清空聊天记录](chat-history-deletion.md)。

每条记录新增可空 `image`，非空时包含本站 `url` 与缓存的 `width`、`height`。图片地址为认证接口 `GET /wechat/api/v1/accounts/{aid}/conversations/{cid}/history/{mid}/image`，复用聊天可见性及用户、账号、会话、消息范围，释放数据库连接后在有界后台调用内读取PNG并核对SHA-256及尺寸；响应禁止缓存。未登录返回401，素材不可用或不在可见范围统一404，不开放媒体目录或接受客户端文件路径。

状态筛选统一使用「全部状态、回复开启、回复关闭、回复暂停」；好友另有「好友已删除」，群聊另有「已不在群聊」（含主动退群、被移出及解散，行内仍展示具体原因）。好友删除及暂停的列表标记与筛选用词一致，恢复成功提示为「回复已恢复」。接口共用 `status=removed`，仅匹配尚未恢复的关系记录，可组合搜索与分页；切换好友／群聊保留筛选条件。「全部状态」继续包含这些记录，历史消息保留规则不变。

助手设定沿用 Vditor 4.0.0 即时预览，不增加格式工具栏、保存按钮或常驻保存条。停止输入约1.5秒保存草稿，结束编辑后整份原子生效，异步回执不能回填正文；中文组合输入、冲突处理、源码切换和快捷键遵循 [自动草稿](assistant-settings.md) 与 [编辑器规则](assistant-settings.md)。主题更新不得重建编辑器或改变这些时序。

### 系统设置

系统设置保留上下排列、等宽的微信接入与AI模型设置两个主面板。桌面面板间距24px，780px及以下16px；保留原有标题栏、页面边距与正文滚动方式。

微信接入采用两行：第一行标签、Token输入框和右侧紧凑保存按钮，第二行标签与只读回调地址；说明紧随地址并与输入框左边界对齐。桌面正文24px内边距、行距24px，780px及以下改为标签在字段上方、保存按钮位于底部右侧，正文内边距及行距16px。回调仍为36px高、12px字号的只读单行输入框，窄屏在框内横向查看，不换行或省略原值；点击及Enter/Space复制保持不变。

AI模型设置面板可用宽度至少980px时，智能回复、语音转写、天气查询等宽三列，以细竖线分隔；不足980px时上下排列，改用横向分隔线。各组标题与配置状态同行，型号／API Host在上、API密钥在下；字段间距16px，分组正文24px内边距，780px及以下左右16px。按钮保持36px高、紧凑右对齐，三个桌面按钮位于同一水平线。

三个标题中的供应商名称均链接至对应官网，复用现有标题文字样式与悬浮下划线，以新标签页打开并设置 `rel="noopener noreferrer"`。目标分别为 [DeepSeek官网](https://www.deepseek.com)、[阿里云百炼官网](https://www.aliyun.com/product/bailian)、[和风天气官网](https://www.qweather.com)。

每组“API 密钥”标签右侧放置“获取 API Key”文字链接及外链图标，不增加说明行；链接使用品牌文字色，具有悬浮下划线与可见键盘焦点，以新标签页打开并设置 `rel="noopener noreferrer"`。目标分别为 [DeepSeek密钥管理](https://platform.deepseek.com/api_keys)、[阿里云百炼北京地域密钥管理](https://bailian.console.aliyun.com/cn-beijing/model/settings/api-key)、[和风天气项目管理](https://console.qweather.com/project)。外链位于label外，不触发表单提交，页面草稿保持不变。

## 提示与动效

操作进行中文案统一为“动作＋中”，不带省略号，例如“登录中、发送中、保存中、绑定中、恢复中”。只有当前操作的控件显示进行中，被连带禁用的控件保留原文案；发送验证码时登录及联系方式确认按钮保持原文案。读取、搜索和同步保留必要对象，沿用现有标题栏或控件；状态结束或失败后恢复，不新增提示组件，不改变按钮尺寸。

系统提示只展示本地维护的简短中文，不显示原始接口异常、堆栈或内部字段；业务正文及文件内容保留原样。

通知统一使用顶部浮层，6.5秒消失，同文案重触发重新计时，原生账户弹窗内仍可见；成功和普通信息使用 status，错误使用 alert。提示不占据页面或表单布局。成功后刷新失败显示「操作已完成，请刷新页面」，不自动重放写入。

保留当前控件160ms、内容200ms、弹窗240ms动效及减少动态效果设置。快速切换取消旧动画，退出中的浮层保持不可交互；动效不得影响焦点、认证、请求、草稿或业务授权。

系统设置的提交状态限定在对应业务区域，不触发全局禁用或全量回读。短暂提交使用 `aria-busy`、`aria-disabled` 与同步防重入保护，保留控件颜色及几何尺寸；真正不可用的状态继续使用原生禁用外观。模型写入串行，开关保存不冻结密钥草稿，密钥保存仅冻结已提交字段。保存响应直接应用，局部轮询与写后回读共用不重叠入口，写入前发起的旧快照不得覆盖回执；回读失败不改变已成功的提交结果。

## 验收与发布

本地或 CI 可执行静态检查、前端测试及构建；浏览器验收使用隔离环境、真实候选构建与内存 API 夹具，覆盖全部页面、组件状态、桌面／窄屏／短窗口、长名称、空列表、异常及展开表单，不调用生产供应商或修改生产业务数据。

- `evals/acceptance/frontend_theme_browser.py` 比较生产基线与候选的关键组件几何尺寸，允许1 CSS px舍入差异；覆盖验证码单表单、邮箱／手机号、获取验证码、冷却、发送中及失败状态，检查正文、占位文字、只读字段与渐变端点的对比度、无横向溢出、键盘焦点和减少动态效果，并保存页面及交互状态截图。
- 复用 `prompt_editor_browser.py`、`reply_scope_layout_browser.py`、`top_notices_browser.py` 回归编辑、草稿、组合输入、账号切换、回复范围和通知行为。
- 生产复用现有 Chrome 登录态检查真实界面，不触碰用户未保存草稿，不擅自换绑联系方式、上传头像、修改密钥或发送业务操作。
- 发布复用 `deploy/update.py` 与既有备份保留入口，核对实际源码、所有前端资源哈希、API／Worker版本和健康；实时停站标记优先，保持既有公网与Worker状态。未完成业务验收的回滚材料继续保护。

### AI模型设置

分区命名为“智能回复 · DeepSeek”和“语音转写 · 阿里云百炼”，配置状态统一“已配置／未配置”，已配置密钥的占位文字为“留空保留原密钥”。模型名称使用只读输入框，位于对应密钥上方；保持官方型号完整可见；底部仅保留“保存密钥”，两组密钥仍按用户独立加密保存。思考模式固定关闭、联网搜索固定开启，不提供开关。同面板增加“天气查询 · 和风天气”分区，API Host 与密码类型的 API 密钥上下排列，独立“保存配置”。首次两项必填，后续密钥留空保留；自动读取保留正在编辑的 Host 和所有密钥草稿。配置状态仅表示完整配置已保存，保存时不查询天气。不提供超时、输出额度或并行任务数输入。回调地址保持只读，点击或Enter/Space复制，结果统一使用顶部短提示；复制失败选中原地址供手动复制，不单列复制按钮。
