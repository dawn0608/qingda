# 关系核实结果承接与共享

## 承接规则


监测初始化和 Worker 扫描现在先承接近期有效查询，再决定是否暂停或排队。好友共享同账号最新完整通讯录结果；群聊承接对应群成员查询。保存原查询起止时间，1200 秒有效期及下次检查时间均以原结果为准。初次承接正常关系不会额外改变会话版本、白名单或取消任务。

发布核对又复现账号回复规则版本由 7 变为 8 后，终端及微信身份未变，但旧版关系证据被判失效的问题。关系核实现在以账号 ID、微信 ID、当前 AppID 和终端操作标识匹配身份；回复规则版本继续保留作追踪与发送任务保护，不再使有效关系查询失效。修改提示词或自动回复开关，无需重新等待通讯录冷却。旧版因此错误暂停的监测行也可承接原查询并恢复。

新的完整通讯录结果在条目替换前同步应用到相关会话，保留被移除联系人的最后昵称与资料。此前有可信好友基线且新名单缺失时标记删除；没有基线时保持待核实，不推断删除方向。成功重新添加后沿用原会话，自动回复白名单继续关闭。

查询失败暂停后的成功核实可以解除暂停，保留原白名单；恢复水位使用当前提交时间，取消的任务和暂停期间的旧消息不补发。被删除关系恢复和查询异常恢复使用不同的白名单规则。

## 证据约束

- 仅承接成功完整全量结果或有效群成员结果；通讯录缓存不能作为关系证据。
- 核对账号、当前终端、终端操作标识、关系版本和 Worker 租约；账号归档、跨账号和终端切换仍使结果失效。
- 过期、未来时间、更新查询失败或在途查询、未处理关系事件均阻止旧结果承接。
- 查询开始早于最近删除或恢复依据时不能覆盖当前关系；保留原事件、关系版本和查询证据。
- 已覆盖的排队请求合并，在途任务继续依赖自己的租约与版本检查。
- 本站页面读取不触发外部查询；账号页仍仅进入或刷新时查询一次。
