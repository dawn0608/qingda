# 最小备份与存储回收

本机和生产环境默认不额外备份。普通发布及不丢失原始数据的迁移无需数据库或媒体副本。仅当本次操作会不可逆地损坏核心且无法重新取得的数据时，复用已有恢复材料；存在缺口才保护最小必要范围。唯一历史业务原件和用户明确要求留存的评测原件继续保留。

## 发布与恢复

发布、例外保护和清理共用 `/run/lock/qingda-release.lock`。运维中转及例外材料位于 `/var/backups/qingda`，不写入源码树。常规发布不创建数据库 dump、媒体包、源码归档或配置备份；依赖未变化时复用当前环境，变化时移动环境并使用临时路径链接。源码通过移动原文件保留切换事务，健康与实际运行版本核验后立即回收候选和过渡目录，只留下小型发布回执。

发布失败且结构未变化时恢复已移动的源码、运行环境和本次进程内存中的配置正文；结构已提交或状态不确定时，保留最新数据库、回调缓冲和必要事务材料，使用兼容修复版本。进程崩溃后依据 `transition.json`、`runtime-transition.json` 和当前实际版本处置；不自动回放业务。已完成发布的代码回滚从 Git 指定提交及锁文件按需重建，通过正常发布入口安装，不能以旧库覆盖新数据。旧 `--rollback` 入口仅用于尚有完整材料且结构兼容的历史发布，不再为它生成新备份。

`receipt.json` 的 `qingda-release-v2` 格式只记录版本、结构及 `runtime_verified`；`business_verified` 单独记录，清理不伪造业务验收。未验收的真实业务结果继续按原验收文档说明，不要求为此永久保留可重建代码和依赖。

## 核心数据例外

默认日备定时器及服务已移除，发布器同时停用并移除服务器旧单元；不设置固定日备份数或周期恢复演练。手工入口必须明确原因、结束条件，以及逐表、逐文件范围：

```sh
/opt/qingda/.venv/bin/python /opt/qingda/deploy/server.py backup \
  --reason '本次不可逆变更涉及无法重新取得的核心原件' \
  --release-condition '对应变更与恢复能力核验完成，且不再需要此副本' \
  --table public.example_table \
  --file /etc/qingda/master.key
```

命令中的表名为示例，须替换为实际范围；不能使用通配符、目录或未明确的全库范围。先审查外键、序列、解密密钥和关联文件等恢复依赖，逐项列入必要范围。文件限定为项目配置、数据目录的常规文件及根 `.env`。数据库导出使用一致性快照；每份检查完成、哈希和可读目录，回执明确 `restore_check: false`，不会将目录校验冒充实际恢复。首次使用或范围、恢复方法改变时，只在隔离库验证该范围的恢复；无关发布不重复演练。优先使用已配置远端；未配置时允许此最小本机临时副本，不自动新增存储平台。

结构变化时，`update.py --migration-review <JSON>` 必须提供 `from_schema`、`to_schema`、`target_revision`、布尔值 `data_loss` 和审查原因 `reason`。不丢失原始数据时 `data_loss: false`，无需备份。核心原件存在不可逆损失时另提供 `required_tables`、`required_files`、`release_condition`，并以 `scope_verified: true`、`restore_verified: true` 记录已完成的范围及恢复审查；缺失或不明确则拒绝变更。

有损迁移在排空任务、停止业务服务并核验 PID 为零后，才按审查范围建立最终保护点，再执行迁移；保持现有运维锁，不允许破坏仍接收回调的 `public.migration_inbox`。可选既有 `recovery_point` 必须连同 `recovery_manifest_sha256` 固定清单，且完成状态、表/文件范围及哈希全部匹配；它不能证明停写前的最后数据状态，因此不能替代发布器停写后建立的最终最小保护点。没有本次不可逆损失时不走此流程，不因结构版本变化而全量备份。


## 清理

`BACKUP_RELEASE_KEEP`、`BACKUP_DAILY_KEEP` 均默认 `0`，临时中转复查时限 `BACKUP_TRANSIENT_TTL_HOURS` 默认 `24`。这些参数不生成备份，也不自动解除历史保护。历史日备及旧格式发布目录需在确认无唯一数据后标记 `cleanup_reviewed: true` 才进入普通轮转；未经审查、失败或仍被引用的材料保留。

`deploy/storage_retention.py` 默认预览，`--apply` 执行既有分类轮转。对受保护目录中的明确冗余文件，使用 `deploy/selective_cleanup.py <manifest.json>` 预览，加 `--apply` 执行。清单声明备份根及逐文件路径、用途、SHA-256 和文件身份；所有候选先完整校验，再逐项复核删除，拒绝越界、符号链接、挂载点及进程引用。清理状态与业务验收分开，不能用新的无关发布接受旧任务。

源码、依赖和旧安装包可根据 Git、锁文件或已结束用途清理；唯一数据库原件、媒体、评测输入输出及必要恢复说明不能仅凭名称、年龄或标签删除。可按文件缩小历史目录；同一文件的重复副本须有内容等价证据。保留原历史清单，并用独立清理回执说明删除、去重及恢复位置变化，不篡改历史验收。无法证明冗余的核心原件继续保留，不能为清理逐份恢复全部历史库。

直接回收确认无用的内容，不再复制或归档待删目录；避免反复扫描、压缩和校验历史。回收记录路径、原因及实际释放空间，失败或跳过项如实报告。
