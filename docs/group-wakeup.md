# 连续对话窗口与群聊、私聊拍一拍


## 规则

账号和群自动回复开启、未处于人工暂停时，真实 @ 本账号、普通文本开头精确呼叫本账号昵称、其他成员拍了拍本账号可以触发自动回复。

- 文本呼叫允许前导空白；`@名字` 后必须是空白、结束或 `，。！？：；、,.!?:;`。名字来源为核实后的账号昵称和本群成员资料中的本账号昵称；大小写精确匹配，不使用备注或模糊匹配。
- 协议已有 @ 名单时以名单为准。仅 @ 其他人或所有人不触发。引用和合并转发内部的 @ 不触发；单条复制、转发成为普通文本且满足开头规则时可以触发。
- 拍一拍只接受可信当前终端、明确群标识、明确操作者和目标的 `10002/pat`。目标必须为本账号，操作者必须为其他成员，正文前缀和参与者不能冲突。其他系统通知仅保留记录。
- 自动回复关闭、人工暂停、未核实关系、历史同步、过期、撤回等仍按既有保护拦截。三种方式均不解除人工暂停。

## 实现契约

新消息 metadata 的 `wakeup_reason` 固定为 `mention`、`text_call`、`pat`、`continuation` 或空值；`mentioned` 继续仅表示微信协议真实 @。计算结果入库后不因昵称变化重算；不重新触发历史跳过记录。拍一拍额外保留操作者和目标 ID，任务发送人使用真实操作者，模型输入使用明确的拍一拍事件描述。原始回调及网页系统提示不改写。

入队、Worker 发送前和未回复计数使用一致的唤醒依据。沿用现有串行队列、同成员合并、撤回失效、去重及重启恢复；不新增支付、系统通知回复或模型供应商，不改变账号提示词。

## 验收

生产事件 215 的文本呼叫、201 的拍一拍、229/234 的人工暂停用于脱敏回归，见 `backend/tests/test_group_wakeup.py`。服务器隔离数据库覆盖文本边界、协议优先、昵称和账号隔离、错误参与者、系统卡片、计数、重复投递、重启、同成员合并和发送前接管；本地可执行静态检查和前端验证，完整后端回归沿用专用服务器隔离环境。

生产手机对照限“微信自动化测试群”：真实 @、纯文本呼叫和拍一拍各验证一次；普通群聊、提到其他人及暂停期间不回复。不向“一家人”补发历史回复。实际版本、备份目录、隔离回归结果和手机样本 ID 保存于本次发布目录的验收记录；无手机样本的范围不得标记通过。

## 连续对话与拍一拍协调

- 群聊按账号、会话、成员隔离。明确唤醒开启一轮对话，实际回复成功后续期至空闲 120 秒，单轮最多 600 秒；明确唤醒也不能突破该轮上限。到期后需再次唤醒。已合法入队的任务不因自然到期取消，仍遵守消息时效和发送检查。
- 协议明确发给其他人、所有人，或普通文本开头呼叫其他名字时，不续聊、不续期。窗口内只接受现有文本、引用文本、图片、语音和表情。
- 拍一拍首次等待 3 秒，重复拍一拍不延长截止时间；等待不占模型并发，也不阻塞同账号其他会话。冻结前同成员问题可合并，其他成员只作为背景，不成为待答问题。
- 先问后拍最多引用近 120 秒的 5 条未唤醒消息。原跳过任务保留审计状态，输入关联唯一，不重新创建自动任务。旧版本消息、撤回、历史同步、暂停期间、明确发给其他人和已处理的消息不回收。
- 私聊按事件 277 的身份结构校验：操作者是当前联系人，目标为本账号，chatusername 可指向本账号或当前联系人。缺失、冲突和本账号发起的拍一拍只展示。
- 私聊排队问题与拍一拍合并；正在生成或发送时只建立关联，不重复生成相同问题。已回复的问题不重答，新的拍一拍可单独回应。冻结后的新问题另排队。
- 群聊近期 2 分钟内已回答同一成员的问题时，随后纯拍一拍等满 3 秒仍无新问题，只续期开窗并关联已回复任务，不再补发寒暄；等待内有新问题仍正常合并回答。这是生产事件 283/284 手机反馈后的调整。
- 人工接管、自动回复关闭及权限版本变化使窗口失效。撤回唤醒消息关闭对应窗口、取消依赖；撤回关联问题时重建未发送批次。发送中的任务保留真实结果，不重发。

`dialogue_windows` 保存授权和固定期限；`reply_input_links` 保存拍一拍、向前关联与输入归属；`reply_not_before` 保存最早执行时间。`dialogue_policy` 记录发布边界，重启不重置。原始回调、聊天正文和系统提示保持原样，模型仅收到清晰事件描述及发送者。关联媒体继续走原下载、转写和容量保护。
