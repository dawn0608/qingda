# 微信自动回复表达

微信自动回复通过普通文本接口发送模型正文，没有 Markdown 渲染。`prompts/auto_reply.md` 统一约束最终输出；账号页面保存的提示词保留身份、交流范围、事实与隐私边界。

- 默认纯文本，不使用 Markdown 标题、强调、代码围栏、引用、列表符号、表格、链接语法、HTML 或 LaTeX 排版。按问题需要列点，用中文序号或 `1、`；内容本身必需的原文、网址、编号、运算符及代码字符保留。
- 简单问题通常一句话，日常聊天一至三句；不设普通回答的硬性字数上限。复杂问题、多问题、写作、代码及详细要求按需完整展开，不靠省略关键内容缩短回答。
- 长度是生成要求，不在发送时机械截断。保留关键条件、数值及必要的不确定性，不重复题意，不添加包装前缀或例行追问；确需澄清只问最关键的问题。
- 原有合并消息、后文更正和“只输出指定值”要求继续适用。历史中的长文本和 Markdown 不作为回复风格示例。
- 写作、改写、通知和转达只使用已提供的事实与要求，不添加新安排、承诺或回复要求。

## 模板职责与账号设定

五份模板分别维护账号身份与交流原则、公共输入及证据规则、私聊差异、群聊差异和最终决策协议。公共表达规则在通用模板集中维护，决策模板只作提交核对；工具 schema 保留字段语义，取消仅因超出200字触发的复核；新增等待控制与固定协议纠错模板，不截断正文或增加普通消息的独立润色调用。前端设定使用 Markdown 编辑，微信发送的 content 使用纯文本，两者不混淆。

新账号由 assistant_default.md 渲染助手名称；文件中的变量说明不进入账号正文。现有账号只在管理员显式执行时同步，启动、刷新和关系恢复不覆盖人工编辑。历史、工具返回、资料和图片文字仅作数据；当前对助手必要澄清的回答应承接仍在进行的需求，不当作已经完成后的确认或补答历史旧任务。

一次性同步使用 scripts/sync_assistant_prompts.py，覆盖全部未归档账号，按账号昵称保留助手名称。默认预览将原文、账号状态和目标文案保存到已登记的本次发布目录，文件不得位于生产源码内；应用须提供预览返回的快照 SHA256。事务复用现有共享锁并锁定账号，先检查全部目标范围、原状态及模板哈希，再更新 prompt、ai_since、epoch、取消旧未发送任务并写入脱敏审计。重复应用不再递增 epoch，不改变自动回复开关、会话允许范围或人工暂停。

```sh
python scripts/sync_assistant_prompts.py preview --snapshot <本次发布目录>/assistant-prompts-before.json
python scripts/sync_assistant_prompts.py apply --snapshot <同一快照> --sha256 <预览哈希>
```

回滚快照随本次发布材料保护至业务验收通过，再按 storage-retention.md 清理。已归档账号和聊天历史不改写。

## 服务器真实模型评测

固定输入和判分版本位于 `evals/acceptance/wechat-reply-style.json`，覆盖闲聊、直接答案、宽泛建议、Markdown 排版请求、历史风格干扰、通知文案、情绪回应、必要澄清、原文字符、关键条件、明确要求详情及代码。输入均为验收材料，不是业务事实。

在生产服务器沿用已配置的 DeepSeek `deepseek-flash`、当前账号提示词和部署模板运行：

```sh
PYTHONPATH=/opt/qingda/backend /opt/qingda/.venv/bin/python /opt/qingda/scripts/evaluate_reply_batches.py --user-id 1 --account-id 3 --case-file /opt/qingda/evals/acceptance/wechat-reply-style.json --output /var/backups/qingda/<本次验收目录>
```

程序逐项检查完整结束、纯文本、字符与段落数量，以及案例要求的关键内容；逐条人工复核回答是否自然、准确且有用。回执保留案例、判分版本、案例文件哈希、部署提交、模板及账号提示词哈希、模型、生成结果和用量。沿用默认案例文件重新验证合并消息的四个固定案例。

批次、工具、图片和长历史评测均支持 --account-prompt-file，读取已经填好助手名称的候选设定，不修改生产账号。新版提示词对照在两个服务器隔离源码目录运行，各用自己的完整装配入口和工具 schema；长历史评测在两个独立源码版本分别运行完整能力，再比较同一固定案例。

统一优化新增固定案例 prompt-unification.json、reply-media-evidence.json 和 reply-source-boundaries.json；后者冻结真实新闻搜索结果，并检查综合天气回答保留来源。关键停止后重唤醒、更正、精确输出、澄清承接、历史隔离与图片归属固定运行三次，失败及修正后的回执全部保留。字符、token、工具描述哈希、生成耗时和模型轮次一并记录。自然度及来源强度需要逐条人工复核，不能只看关键词判分。

评测只读账号及模型配置，不写业务消息、不创建发送任务、不向联系人发送微信。模型评测通过不等于接收端实收验收，也不保证所有开放式输入始终符合要求。修改账号提示词前在服务器受限目录备份原文，核对原文未漂移后只调整表达段落；沿用账号 epoch 及任务取消机制使旧回复失效，保留账号自动回复开关、会话暂停和允许范围。
