# 清空聊天记录

聊天记录搜索栏右侧提供“清空聊天记录”，必须在独立确认弹框再次确认。范围为当前认证用户、当前微信账号及所选好友／群聊；保留联系人、回复开关与账号配置。清空覆盖全部已保存消息，而不受搜索词、分页、撤回或消息类型限制。

同时移除消息正文、原始回调与版本、收件中转副本、搜索投影、转写、媒体定位及理解缓存、对应 AI 任务和上下文，以及该批消息的磁盘原件、像素缓存和解码临时文件。仅保留不含正文和媒体的幂等删除回执及哈希去重标记，防止平台重复回调恢复旧记录。不会操作微信客户端或对方手机中的记录。

清空时先在既有全局短事务中固定范围、提升会话修订并取消旧回复；正在发送时暂不启动，避免发送结果不明。等待旧执行容量归还后清理数据库，文件删除在连接外进行，全部文件清理成功才报告完成。持久租约限制跨进程领取，进程退出、请求断开或清理失败均可由 Worker 续清；失败显示进度和顶部提示，不把部分清理当作成功。确认之后新收到的消息保留，清理期间不生成使用旧历史的回复。

接口为认证与CSRF保护的 `DELETE /wechat/api/v1/accounts/{aid}/conversations/{cid}/history`，请求必须携带UUID `request_id` 及 `confirmed=true`。同一请求重试不再删除之后的新消息。`GET .../history/deletion` 读取已确认操作的进度，Worker也会在后台续清；租约只允许一个进程领取，失败不扩大范围。播放与清理共用固定64路媒体读写锁，临时目录携带消息ID，防止清空后被迟到的转换写回。

本次采用 schema 59 增量表保存删除进度，启动不自动迁移。按钮清理当前数据库与媒体存储，不改写包含其他会话的既有日备、发布回滚材料或运维证据；这些材料继续遵守 [备份保留规则](storage-retention.md)。当前数据库清空不等同于磁盘取证意义的安全擦除。
