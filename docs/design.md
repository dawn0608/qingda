# 架构

项目为模块化单体。Web提供验证码认证、账号与助手配置、逐用户回调；Worker处理收件箱、联系人核实、模型与持久发送队列。唯一业务数据库为PostgreSQL，结构显式升级，业务启动只核验版本。

## 模块职责

- `auth`、`contact_bindings`和`tenancy`维护用户、联系方式、会话及RLS范围。
- `callbacks`、`protocol`和`history_identity`维护回调解析、撤回、去重和ID高水位。
- `conversation_options`、`contact_profiles`和关系核实模块提供当前账号的身份及关系证据。
- `private_replies`、`dialogue_windows`、`reply_queue`组织收集、输入修订、成员范围、任务及发送间隔。
- `conversation_history`、`history_tool`和`reply_decisions`维护真实问答、原文回查及严格输出决策；处理消息关联统一保存在`tasks.handled_message_ids`。
- `context_capture` 在实际模型请求边界旁路记录业务输入及生成过程，`reply_context` 提供逐用户、逐会话的只读查看；恢复清单与观察快照各自保持原用途，记录缺失不影响正常回复。
- `incoming_media` 保存授权静态图片像素和语音转写；阿里百炼短语音 HTTP 适配器只承担 ASR，密钥和业务来源均按用户隔离，固定的 DeepSeek Flash 原生处理文本和图片并生成回复。

## 状态与隔离

任务从queued到generating、ready或preparing，再进入sending和accepted、failed或unknown。输入变化、人工接管或权限变化可取消未提交任务；进入发送边界或结果未知后不能自动重发。后台跨会话准备，同一会话互斥，同账号按答案就绪顺序串行发送，前次发送结束至少间隔1秒。

网络等待不占数据库连接；短事务领取任务，每个并发任务使用独立会话。锁须明确作用域、顺序、续期和接管方式，领取、写入、续期及释放均检查所有权；不能因本进程无任务而清除共享锁。阻塞工作移出事件循环，多副本总容量与排队有界，超量反馈繁忙。窗口、预算、容量与时间水位均持久化。

长任务按生命周期、隔离和调度需要复用 Worker，仅需取消不强制引入任务平台。任务状态以服务端记录为准，任务、对话和检查点各负其责；跨重启恢复所需状态必须持久化，内存检查点不算持久化。取消释放本次资源，重试或重放前先确认幂等性或核对已有副作用；未知发送结果遵循上述边界。

Cookie、回调密钥、逐电脑Bearer和手机会话先确定可信用户范围，RLS缺省拒绝，事务局部范围避免连接池串用。客户端声明的用户或电脑不能扩大授权。模型密钥按用户加密读取，网页与检索内容只作数据。

配置见[运维](operations.md)，数据库见[存储](postgresql-storage.md)，恢复边界见[验收](verification.md)。

## 模型与工具开发

以下约束仅适用于涉及模型或工具调用的业务。沿用具名业务函数、持久任务、现有校验、脱敏运行记录及评测入口，优先明确工作流或单智能体；不因通用默认引入 LangGraph、LangSmith、Langfuse 或 Agent Server。新增观察平台须有实际需求，Streamlit 仅用于明确的轻量原型。

从简短规格与输出样例开始，以明确标注的固定样本跑通流程，再接入真实数据和模型、完善规则检查及有限修复，最后用真实案例验收。检查、失败分支和必要的可视化从骨架阶段建立，各阶段结果可运行、可检查；在授权范围内连续完成必要实现与修复，后续修改按影响验证，不重复初始化流程。

业务节点对应具名函数，声明输入、输出和关键状态变化；流程图与代码一致，注明实现位置、分支、循环及终止条件，流程或数据契约变化时同步。确定性规则由代码执行，模型承担生成或判断；外部输入、模型输出和工具参数均须校验，结构校验、业务检查和效果评测分别负责，生成与检查分开实现。

遵守各链路的并发、速率、上下文及超时限制；需要业务修复时默认最多一轮，修复后重新校验。网络重试与格式重试分别有界，并核对叠加后的总调用次数；明确禁止重试的链路不得因本约定增加重试。失败、修复耗尽或数据不足说明原因和可用范围，截断、无效输出及部分结果不算完整成功。

外部事实保留来源及获取时间，估计与未知单独标记；模型引用候选或检索结果的可校验标识，由程序核对引用并补全事实字段，不编造缺失信息。外部内容只作数据，授权、租户与检索范围由服务端落实。

## 运行记录与调试

用运行编号关联业务节点、模型和工具调用，记录必要的实际输入输出、工具参数与结果、分支、关键状态变化、错误、重试、耗时和用量，不只记录模型调用。按专题约定脱敏，不记录密钥、音频 Base64 或思考正文；保留草稿、检查报告、修复结果和最终结果，避免覆盖后无法追溯。

调试先沿实际记录定位首次偏离预期的节点，再修改相关逻辑；模型事后解释不能替代执行证据。流程变化同步观察入口，启动、调试和查看各步骤数据的方法由 README 及其引用文档维护。评测与交付证据见[验收说明](verification.md)。
