# 验收

## 当前检查范围

本地仅执行必要的文档、静态检查及发布构建，不启动空数据环境做业务验收。现有 GitHub CI 执行 README 中的 Ruff、前端 Node 测试和 TypeScript/Vite 构建，无需生产数据。默认 CI 不运行完整后端回归，不证明真实模型效果、生产功能或手机实收。

完整后端回归继续使用专用 Linux/PostgreSQL 隔离环境，显式配置 `TEST_DATABASE_URL` 后执行 `uv run python scripts/check.py`。数据库名必须含 `test`；夹具会建删临时 schema，部分用例还需要 root/peer、`runuser`、`psql`、Nginx、OpenSSL、FFmpeg 或已准备的浏览器构建，不能使用生产库。仅在具备这些条件且明确隔离的环境中执行该入口，不以 SQLite 替代。

## 验证与交付规则

依据已确认需求与权威契约按改动影响选择 lint、独立类型检查、相关测试、构建和浏览器核验；示例不新增限制，普通文档、文案或样式改动不触发无关数据库、并发或模型评测。修复本次缺陷后复验，使用脱敏运行编号关联调用。

核心回归包括用户隔离、验证码额度、回调去重、助手草稿、回复关联与媒体、原生备份恢复。跨进程状态改动以至少两个独立进程验证重复领取、超量、取消、崩溃、过期接管及回执丢失；不对生产业务制造故障。

新库与升级库比较结构、约束、RLS、权限和有效数据。生产交付核对源码、API、Worker和前端版本与哈希。

程序测试、真实模型效果、生产功能、手机接收分别记录。供应商替身只证明程序契约；模型质量沿用 `evals/` 固定案例和已授权真实评测。未验证项不算通过，受保护材料继续保留。

## 模型与工具评测

- 首次业务评测在根 `evals/` 按业务维护固定案例与判分，纳入真实失败；提示词、模型、工具、检索或业务流程变化比较相关案例，追踪代码、提示词、模型及评测版本、结果、耗时和用量。
- 按业务覆盖正常及非法输入、数据缺失、接口失败、无效输出、修复耗尽与历史失败；依据业务约束和质量标准判分，不要求开放式生成逐字相同，不为规范新增完整评测平台。
- 新功能验收至少提供一条脱敏、可检查的端到端运行记录，README 及其引用文档说明启动、调试和查看步骤数据的方法。固定样本须明确标注，不能当作真实联调；缺少密钥时先完成可验证部分并说明缺口，真实评测只在授权范围内执行。
- 交付用简明中文说明本次验证环境、结果及限制；草稿、失败、检查报告、修复结果和最终结果分别保留，不覆盖失败回执或将部分成功记为完整通过。
